# Obsidian 完整环境迁移

完成一次可验证的「源库 → WebDAV → 目标库」迁移。实际调用时确定源库、目标库与可用插件产物；复用用户已授权的连接和迁移范围，不把此文件中的示例视作授权。

## 适用版本与输入

- 目标库需要安装具有“同步完整使用环境”和“从云端恢复完整使用环境”的定制版。已验证版本为 0.5.27；不能只凭版本数字认定其他发行版具备这些功能。
- 优先使用用户已有、来源明确的定制安装包，或源库中正在使用的同一插件版本。核对 `manifest.json` 中的 ID 为 `remotely-save`，并确认 `main.js`、`manifest.json`、`styles.css` 齐全。
- 本仓库只保存源码更新与工作流，不提供可安装插件。不能把社区市场原版当成定制版，不能从这些补丁直接推断产物完整。涉及重新构建时先阅读仓库 README 的基线和 Pro 许可范围；没有必要授权时不要修改或分发上游 Pro 代码。
- 用户指定路径优先。Mac 可读取 `~/Library/Application Support/obsidian/obsidian.json` 的 `vaults` 定位现有库；不要硬编码用户名或把个人路径写回此 skill。
- 源库不可用时，需要用户指定云端目录和连接来源。只在缺失信息影响执行时询问；不得猜测密码、加密方式或远端库名。

## 1. 识别并备份

1. 确认源库与目标库的真实路径不同，且互不嵌套。确认实际配置目录，通常是 `.obsidian`；非默认目录需从应用核实。
2. 读取两端插件版本、安装/启用插件数量、主题数量、内容文件数量及总字节数。仅输出必要摘要；不得输出 `data.json`、账号、密码、令牌或笔记正文。
3. 将目标库备份到库外、唯一时间戳目录；大库可采用已验证可恢复的备份方式。至少保存目标插件、完整配置目录和会被覆盖的内容。记录备份位置。
4. 在源库开启“同步完整使用环境”，完成一次真实同步，确认成功。若远端已是最新且有可靠成功记录，可直接验证。空跑成功不能代表内容已上传。
5. 写插件文件或离线编辑设置前，正常退出相关 Obsidian 进程，等待退出。重启后先确认当前窗口属于正确的库；用户切换窗口时重新读取状态。

## 2. 安装并绑定同一个远端目录

替换目标库配置目录下 `plugins/remotely-save/` 的程序、清单和样式。不要复制源库的整套配置来冒充云端恢复，不要复制源库同步数据库或设备库 ID。

源库的连接配置可在用户授权的本机迁移范围内复用。配置可能是明文，也可能是 `{readme, d}` 混淆格式：`d` 是 UTF-8 JSON 的无填充 base64url，再反转字符串。混淆不是加密。可使用以下局部函数解码和重新编码，值始终留在内存中：

```python
import base64, json

def decode_settings(raw):
    if isinstance(raw, dict) and "readme" in raw and "d" in raw:
        encoded = raw["d"][::-1]
        return json.loads(base64.urlsafe_b64decode(encoded + "=" * (-len(encoded) % 4)))
    return dict(raw)

def encode_settings(settings, original):
    if "readme" in original and "d" in original:
        encoded = base64.urlsafe_b64encode(
            json.dumps(settings, ensure_ascii=False, separators=(",", ":")).encode()
        ).decode().rstrip("=")
        return {"readme": original["readme"], "d": encoded[::-1]}
    return settings
```

迁移前核对并设置：

- `serviceType = "webdav"`，复用正确的 WebDAV 地址、认证方式、账号、密码、自定义头及端到端加密密码/算法。保留确实在用的账户与智能冲突设置；不要为了绕开错误降级冲突策略。
- **明确填写目标的 `webdav.remoteBaseDir`**。此客户端的实际目录为 `源设置.webdav.remoteBaseDir || 源库名称`。原值为空时，目标必须填源库名称，否则会错误连接目标库自己的空目录。不要更改源库目录，也不要另建一个“迁移目录”。
- 首次目标同步用 `syncDirection = "incremental_pull_only"`，`syncConfigDir = false`、`syncBookmarks = false`。环境稍后单独恢复，避免新库的默认配置参与冲突。
- 暂停目标 `autoRunEveryMilliseconds`、`initRunAfterMilliseconds`、`syncOnSaveAfterMilliseconds`，均设为 `-1`。记录用户原来的自动同步偏好，以便完成后恢复。
- 移除从源设置复制来的旧式 `vaultRandomID`，让目标库初始化自己的同步身份。保留目标已有身份，避免复制源库数据库。
- 记录过滤规则、大小阈值及下划线文件开关；不要静默清空它们。用户要求的文件若被过滤，应说明并按用户范围调整。
- 保证目标 `community-plugins.json` 包含 `remotely-save`；保留其他本地插件，除非用户要求替换。

本地敏感备份放在库外并限制访问，不加入 Git，也不要放进会被同步的目录。

## 3. 实际拉取笔记

1. 打开目标库，核实窗口标题、插件版本、WebDAV 实际目录和单向拉取设置。
2. 执行 `Remotely Save: 开始同步（start sync）`。`开始同步（空跑模式）` 只生成计划，不能代替这一步。
3. 等待真实同步结束。WebDAV 递归枚举可能先持续一段时间；结合状态栏进度、落盘文件数和错误信息判断，不要重复点同步。
4. 失败时检查原因；保留已下载文件和备份。认证、加密、限流等问题未解决前，不开启双向同步，也不无限重试。

## 4. 从云端恢复环境

1. 在目标 Remotely Save 设置或命令面板选择“从云端恢复完整使用环境”。填写**源库**的配置目录名，通常是 `.obsidian`；恢复结果写入目标当前配置目录。
2. 等待“已恢复 N 个使用环境文件”提示，记录插件生成的本机备份目录。恢复会先下载、校验，再写入；启用插件列表最后写入。若提示配置不完整、JSON 无效或回滚失败，先处理问题，不要强制启用插件。
3. 成功后立即正常退出并重新打开 Obsidian。重启前不要继续同步，避免内存中的旧设置写回。
4. Remotely Save 自身、连接配置、恢复备份、`workspace.json` 与 `workspace-mobile.json` 按设备保留。这些文件不属于跨设备完全相同的验收范围。

## 5. 验证与交付

- 源库可用时，对迁移范围内笔记及附件比较相对路径、大小和 SHA-256；配置文件在恢复后、重启前比较，重启后某些插件会正常改写运行数据。不要只比较数量。
- 核对主题、插件清单和程序完整性，比较 `appearance.json`、`hotkeys.json`、`community-plugins.json` 以及用户要求的插件配置。对过滤排除项、迁移期间源文件变化、远端额外文件单独解释。
- 保留目标原有额外文件。新库默认欢迎页如果确实未修改且已备份，可移到库外备份中，避免随后上传到源库；不要删除未知内容。
- 检查应用实际加载结果。插件安装数量相同不代表全部能运行；记录当前 Obsidian 阻止的旧版本或平台不兼容插件，不把它们报告成迁移丢失，也不擅自更换版本。
- 验证通过后才设置 `syncConfigDir = true`。只有用户要求持续互通时，改回 `bidirectional` 并恢复其自动同步偏好；一次性恢复保持自动同步关闭。写离线配置仍需先退出应用。
- 重启后运行一次同步预检，确认连接和配置有效。分别报告“真实内容同步完成”和“后续预检成功”；不要用预检更新时间推断又完成了一次真实上传/下载。
- 最终给出目标库、插件版本、已核对数量、备份位置、后续同步方式及实际阻塞项。不要输出连接凭据。

## iPhone / iPad 分支

没有可操作的手机接口时，给出人工步骤，不声称已安装或验收。使用 App Store 的 **Obsidian – Connected Notes** 创建本地库，安装同一定制版；市场原版不能替代本 skill 所需的环境恢复功能。手动安装必须能写入目标库实际配置目录，不能只把 ZIP 放到“文件”中就算安装成功。

连接与电脑相同的 WebDAV 地址、认证、加密及**明确的源远端目录**，先拉取内容，再运行环境恢复。成功后从多任务界面彻底退出 Obsidian 并重新打开。桌面专用插件即使程序已同步，也不能在 iOS 运行。实际文件安装工具和可访问路径需按用户设备核实，不固定依赖某个第三方编辑器，也不需要修改 Obsidian 或提供 IPA。

## 已知故障定位

- `Failed to fetch` 若发生在智能冲突的账户刷新阶段，检查定制构建的官方账户服务配置。0.5.27 已修复构建变量为空导致请求本地相对 `/api/v1/oauth2/token` 的问题；保留原账号设置，安装已验证修复包后验证真实账户刷新和 WebDAV 连接。不要把所有网络错误都归因于此问题。
- 目标远端为空时，先检查有效目录是否误用了目标库名称，再检查源库是否完成真实上传；不要上传新库默认配置去“初始化”旧库远端。
- 普通同步下载环境后提示重启时，先重启再操作；不要绕过插件的暂停标记。
